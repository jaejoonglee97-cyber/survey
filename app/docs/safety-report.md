# 보안·개인정보 점검 보고서

- 점검일: 2026-11-09
- 기준: `survey-platform-handoff/docs/06-safety-checklist.md`(Supabase 기준 항목은 구글 시트 구조에 맞게 바꿔 적용)
- 범위: `app/` 전체 코드, 로컬 더미 데이터 모드에서의 동작
- 이 문서는 법률 자문이 아님. 실제 운영 전 기관 정보보안 담당자의 검토와 승인을 받음.

표기: ✅ 통과(근거 있음) · ⏳ 사람이 할 일(배포·계정 설정, 아직 안 함) · ⚠️ 예외 승인 필요

## 결론

코드로 확인할 수 있는 항목은 모두 통과함. **배포 전에 사람이 해야 할 항목(⏳)과 예외 승인(⚠️) 2건이 남아 있어, 아직 실제 설문을 운영하면 안 됨.**

## 2. 배포 전 체크리스트

### 접근통제
| 항목 | 결과 | 근거 |
|---|---|---|
| 브라우저가 데이터에 직접 접근하지 않음(시트는 서버만) | ✅ | 시트 모듈은 `server-only`, 클라이언트 컴포넌트의 시트 모듈·비밀 변수 참조를 `check:secrets` 가 검사 |
| 열람자는 응답 원자료·설문 관리 불가 | ✅ | `tests/admin`(서버 동작 6종 거부·데이터 불변), 브라우저 확인(담당자 화면 4개 → 대시보드로 이동, CSV 403) |
| 응답 저장은 서버 경로로만 | ✅ | `/api/s/[slug]/submit` → `survey-core` 검증 → 시트 행 추가. `tests/respond` |
| 서버 동작이 역할을 직접 재확인 | ✅ | 모든 화면 `requirePage`, 서버 동작 `commands.ts` 의 `guard`, CSV 라우트 자체 확인. 역할은 요청마다 시트에서 다시 읽음 |
| 크론 경로는 비밀값 없이 401 | ✅ | `tests/jobs`(16자 미만 비밀값도 거부, 시간차 공격 방지 비교), 브라우저 확인 |
| 직원 등록·권한 변경은 시트 `staff` 탭에서만 | ✅ | 앱에 가입 기능 없음. 시트 편집 권한이 있는 사람만 변경 가능 |
| 로그인 허용 도메인 제한 | ✅ | `ALLOWED_EMAIL_DOMAIN` 비어 있으면 아무도 로그인 불가, 구글 `email_verified`·`hd` 확인, `tests/admin` |
| 개발용 로그인은 운영에서 꺼짐 | ✅ | 로컬 더미 모드 + 개발 서버에서만. 운영 빌드(`next start`)에서 버튼이 나오지 않음을 확인 |

### 키와 설정
| 항목 | 결과 | 근거 |
|---|---|---|
| 클라이언트 번들에 키 없음 | ✅ | `check:secrets` 가 빌드 결과에서 키 머리표·서비스 계정 주소·`.env.local` 의 비밀 값을 검색 |
| `NEXT_PUBLIC_` 에 비밀 값 없음 | ✅ | `check:secrets` |
| git 이력에 `.env`·키 없음 | ⏳ | 아직 git 저장소가 아님. CI 에 이력 검사 단계를 넣어 둠 |
| Production/Preview 분리, Preview 는 더미 | ✅/⏳ | Preview 에서 운영 시트를 가리키면 앱이 실행을 거부함(`tests/store`). Vercel 환경변수 설정은 사람이 할 일 |
| 2단계 인증(GitHub·Vercel·구글·메일 서비스) | ⏳ | 계정 설정 필요 |
| 퇴사·인사이동 시 계정 회수 절차 | ⏳ | `staff` 탭의 `active` 를 FALSE 로 바꾸면 즉시 접근이 막히고 결과 메일도 끊김(시험으로 확인). 이 절차를 업무 매뉴얼에 넣을 것 |

### 입력 검증과 인젝션
| 항목 | 결과 | 근거 |
|---|---|---|
| 응답 API: 20KB 제한, 형식 검증, 보기 외 값 거부 | ✅ | `tests/respond`(선언 길이를 속여도 실제 길이로 차단, JSON 만 허용) |
| 사용자 입력은 텍스트로만 렌더링 | ✅ | `dangerouslySetInnerHTML` 없음, HTML 문자열이 글자로 저장·표시됨(브라우저 확인), 기본 CSP 헤더 |
| 시트·CSV 수식 주입 방어 | ✅ | 셀은 RAW 로 쓰고 `= + - @` 시작 값에 `'` 추가, CSV 도 같은 처리(`tests/admin`, `tests/store`) |
| 속도 제한과 응답 수 상한 | ✅/⏳ | 코드: 설문당 1분 240건·전체 600건(인스턴스 단위), 응답 상한 = 대상 인원×3(최소 50, 최대 5,000). Vercel Firewall 규칙 설정은 사람이 할 일 |
| IP·User-Agent 미저장 | ✅ | 저장·로그 코드 없음(검색 확인). 제출 시각도 시 단위로만 기록 |

## 3. 예외 승인이 필요한 항목

| 번호 | 내용 | 위험 판단 | 제안 |
|---|---|---|---|
| ⚠️ 1 | `npm audit`: Next.js 에 들어 있는 PostCSS 취약점(높음 1, 보통 1). 고치려면 Next.js 16 으로 올려야 함 | 빌드할 때 이 앱의 CSS 를 처리하는 부분이라 응답자·직원 입력이 닿지 않음. 실제 공격 경로는 낮다고 판단 | 예외로 기록하고, 운영 시작 전 Next.js 15 의 보안 패치가 나오면 올림. 16 으로 올리는 작업은 별도로(로그인 라이브러리 호환 확인 필요) |
| ⚠️ 2 | 진행 중 설문의 대시보드 중간 집계: 응답 5건 이상이면 진행 중에도 분포가 보여, 열람자가 특정인이 제출한 직후 새로고침해 차이를 보면 그 사람의 점수를 짐작할 수 있음 | 열람자가 직원·이사회로 한정되고 결과가 1분 묶음으로 갱신되어 위험은 낮음 | 받아들이거나, 원하면 "진행 중 설문은 마감 후에만 수치 표시"로 바꿈(작은 수정) |

## 4. 독립 보안 검토 지적과 조치

| 지적 | 심각도 | 조치 |
|---|---|---|
| 공개 제출 경로를 자동 스크립트로 두드려 시트 한도 소진·허위 응답 채우기 | 중간 | 코드 속도 제한 추가(인스턴스 단위), 응답 상한을 대상 인원×3 으로 낮춤. Firewall 규칙은 배포 필수 조건으로 README 에 명시. 1회용 제출 토큰은 v2 후보 |
| 초 단위 제출 시각으로 현장에서 서술 의견과 사람을 짝지을 수 있음 | 낮음~중간 | 제출 시각을 시 단위로만 기록 |
| 권한이 회수된 작성자에게도 결과 메일이 감 | 낮음~중간 | 지금 활성 담당자(admin)에게만 발송, `ADMIN_NOTIFY_EMAIL` 도 직원 목록과 대조 |
| 초안 수정 때 slug·마감일 검사 누락 | 낮음 | 저장 형식에 slug·마감일 형식 검사 추가, 초안 수정도 기본 정보 검사 |
| 열람자가 새로고침으로 대시보드 재계산을 반복 | 낮음 | 강제 새로고침은 15초에 한 번만 재계산 |
| 보안 헤더 부족 | 낮음 | CSP·Permissions-Policy 추가. 개발·운영 서버에서 화면 동작과 CSP 위반 없음 확인 |

검토에서 문제없다고 본 부분: 화면·서버 동작·CSV 의 권한 재확인, 로그인 설정(세션에는 이메일만, 개발용 로그인 차단), 크론 인증, 비밀 값 처리, 입력 검증·수식 주입·XSS 방어, 대시보드로 가는 데이터의 개인정보.

## 5. 아직 확인하지 못한 것

- 실제 구글 시트 연결(서비스 계정 미준비), 실제 구글 로그인(OAuth 클라이언트 미준비), 실제 메일 발송(메일 서비스 미정). 모두 로컬 더미 모드와 대체 구현으로만 시험함.
- Vercel 배포 환경에서의 동작(리전, 크론, Firewall).
