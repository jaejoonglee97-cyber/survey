# 만족도 설문 모듈 - Claude Code 인계 패키지

서사협 회원서비스 사이트에 **'대화형 설문 설계 → 링크 배포·자동 마감 → 결과·대시보드'** 기능을 추가하기 위한 설계·명세 묶음임. Claude Code로 구현하고, GitHub에 올려 Vercel로 배포하는 흐름을 전제로 함.

## 사용 순서

1. 이 폴더의 내용을 기존 사이트 저장소에 복사함(`CLAUDE.md`는 저장소 루트, 나머지는 `docs/survey/` 등 원하는 위치. 위치를 바꾸면 `CLAUDE.md`의 경로를 고침).
2. 저장소 루트에서 Claude Code를 실행하고, `docs/05-claude-code-prompts.md`의 **Phase 0(저장소 파악, 읽기 전용)** 지시문을 붙여 넣음.
3. Phase 0 결과(`00-repo-audit.md`)와 보고된 질문을 확인하고 결정한 뒤, Phase 1부터 9까지 **한 단계씩** 진행함. 각 단계의 완료 기준(시험 통과)을 확인한 뒤 커밋함.
4. Phase 8의 안전 점검과 Phase 9의 시범 운영(더미 설문)을 마친 뒤에 실제 설문을 진행함.

| `docs/01-prd.md` | 요구사항: 사용자, 기능, 화면 목록, 범위 밖, 결정이 필요한 사항 |

| `docs/04-design-system.md` | 기존 '업무 홈' 화면에서 추출한 색·치수, 새 화면 구성, 접근성 보정 |

| `.env.example` | 환경변수 이름(값은 비어 있음, 서버 전용 표시) |

## 이미 검증된 것과 아닌 것

| 구분 | 상태 |
|---|---|
| DB 스키마·RLS·마감·대시보드 함수 | PGlite로 10개 시나리오 통과(익명 차단, 열람자 원자료 차단, 5건 미만 비공개, 마감 후 제출 거부 등). 실제 Supabase 프로젝트에서의 최종 확인은 Phase 1에서 함 |
| 문항 검증·집계·보고서 로직 | 프로토타입에서 서버 20개·화면 5개 시험 통과(`reference/`). TypeScript 이식은 Phase 2 |
| Next.js 코드 | **아직 없음.** Claude Code가 Phase 2~7에서 작성 |
| 대화형 설계의 모델 동작 | 프롬프트·도구·검증 규칙을 설계했으나 **실제 모델 대화로는 시험하지 않음.** Phase 6의 수동 평가(`eval:builder`)로 확인하고 프롬프트를 조정함 |
| 디자인 | 스크린샷에서 색을 직접 추출하고 치수를 눈대중으로 잡음. 저장소의 실제 토큰과 컴포넌트가 우선이며 Phase 0에서 대조함 |

## 시작 전에 정해 두면 좋은 것 (정하지 않으면 기본값으로 진행)

1. 직원 로그인: 기존 사이트의 방식을 재사용(없으면 Google 로그인 + 협회 도메인 제한)
2. Supabase: **설문 전용 신규 프로젝트(서울)** 권장. 기존 회원 데이터와 분리
3. 결과 메일 서비스: Resend(기관이 쓰는 메일 서비스가 있으면 그것)
4. 응답 링크 도메인: 기존 사이트 도메인의 `/s/<slug>`
5. 열람자(이사회·직원) 범위와 보관 기간

## 알아 둘 점

- **서술 의견의 AI 분석은 v1에서 제외함.** 서술 의견에는 응답자가 개인 정보를 적을 수 있어, AI에 보내려면 동의 또는 마스킹 설계가 먼저 필요함. AI는 문항 설계 대화에만 쓰며 응답 원문은 보내지 않음.
- Claude API 키와 사용 비용이 필요함(설계 대화에만 사용되므로 사용량은 적은 편). 키는 서버 전용 환경변수로만 둠.
- Supabase DPA(위탁계약)는 자동 포함되지 않으므로 대시보드 법무 문서에서 **직접 서명**해야 함.
- 새 사이트가 완성되기 전까지는 앞서 만든 Apps Script 버전(`healingcamp-survey.zip`)을 임시 운영 수단으로 쓸 수 있음. 두 버전의 응답 데이터는 이관하지 않음.
- 이 문서는 법률 자문이 아님. 운영 전 기관 정보보안 담당자의 검토를 받음.
