# 01. 요구사항 (PRD)

## 1. 배경과 목적

- 협회 사업·행사가 끝날 때마다 참여자 만족도를 조사하고, 그 결과를 결과보고서에 반영하며, 사업별 성과를 해마다 비교할 필요가 있음.
- 현재는 사업마다 설문 문항을 새로 만들고, 응답 수집과 집계, 보고서 문안 작성이 따로 이루어져 행정 시간이 많이 듦.
- 이 모듈의 목적은 **'어떤 사업이든 대화로 설문을 만들고, 링크 하나로 받고, 결과가 자동으로 정리되어 비교되는 것'** 임. (행정시간↓ → 대면서비스↑)

## 2. 사용자

| 구분 | 설명 | 권한 |
|---|---|---|
| 담당자(admin) | 설문을 설계·게시·관리하는 협회 직원 | 설문 생성·수정·게시·마감, 결과(서술 의견 포함) 열람, 대시보드 |
| 열람자(viewer) | 직원·이사회 등 성과를 확인하는 사람 | 대시보드의 집계만 열람 |
| 응답자 | 사업·행사 참여자(회원) | 로그인 없이 링크로 무기명 응답 |

## 3. 핵심 기능

### 3.1 대화형 설문 설계 (이 모듈의 중심)

- 담당자가 **기본 정보**를 입력함: 사업·행사명, 분류, 사업명(program, 연도별 비교 기준), 기간, 대상 인원, 설문 마감일
- 이어서 AI와 대화하며 **무엇을 알고 싶은지** 말하면 문항이 만들어짐. 화면 오른쪽에는 문항 초안이 실시간으로 갱신됨.
- 담당자는 대화로 고치거나, 문항을 직접 편집(문구 수정, 순서 변경, 삭제, 추가)할 수 있음.
- AI는 **같은 사업(program)의 이전 연도 설문과 집계 결과**를 참고해 비교 가능한 문항은 유지하고 개선점을 제안함.
- AI는 설계 원칙을 지킴: 12문항 이내, 대표 만족도 문항 1개 필수, 이중 질문 금지, 개인정보 질문 금지. (상세: `03-builder-chat.md`)
- 설문 점검(체크리스트) 후 담당자가 **확정**해야 게시할 수 있음.
- 파일(md, PDF)로 올린 문항 초안이나 이전 결과보고서를 불러와 대화의 출발점으로 쓸 수 있음(선택).

### 3.2 배포·마감

- 게시하면 응답 링크(`/s/<slug>`)와 QR이 만들어짐.
- 응답자는 로그인 없이 휴대전화로 응답함(무기명). 마감 시각이 지나면 응답이 즉시 차단되고 설문이 자동으로 닫힘.
- 마감일 연장, 조기 마감이 가능함. 마감되면 결과 요약이 담당자 메일로 1회 발송됨.

### 3.3 결과

- 설문별 결과: 문항별 집계(막대), 5점 문항 평균·긍정 응답 비율, 서술 의견 목록, 응답률
- **결과보고서 문안 초안**(공문서 명사형, 수치만 정리)을 복사할 수 있음.
- 원자료 내려받기(CSV)는 담당자만 가능함.

### 3.4 만족도 대시보드

- 모든 설문의 **대표 만족도 문항(5점)** 을 같은 1~5점 눈금에 올려 사업·행사별, 분류별, 연도별로 비교함.
- 요약(조사 수, 응답 수, 평균, 긍정 응답 비율) → 눈금 비교 → 점수 분포 → 연도별 추이
- 대표 문항 응답이 5건 미만이면 수치를 숨김. 서술 의견은 대시보드에 나오지 않음.
- 참고 화면: `reference/dashboard-preview.html` (예시 데이터)

|---|---|---|

## 5. 비기능 요구

- 모바일 우선(응답 화면), 키보드 조작·화면 낭독 가능, 다크모드는 선택
- 동시 응답 100건/분 수준을 안정적으로 처리(공개 링크 일시 집중)
- 응답 데이터는 무기명, 문항·집계 외 개인 식별 정보 미수집
- 서울 리전 사용, 모든 비밀 값은 서버 전용 환경변수
- 한국어 UI

## 6. 범위 밖 (v1에서 하지 않음)

- AI의 서술 의견 분석·요약(개인정보·국외이전 검토와 동의 설계가 먼저 필요)
- 응답자 인증, 중복 응답 방지(무기명 원칙과 충돌)
- 설문 게시 후 문항 수정(응답과의 불일치 방지를 위해 DB에서 차단)
- 다국어 설문, 조건 분기(건너뛰기) 문항

## 7. 성공 기준

- 담당자가 사업 기본 정보와 대화만으로 **10분 안에** 게시 가능한 설문을 만들 수 있음
- 응답 소요 시간이 **3분 이내**임(문항 12개 이내)
- 마감 후 결과보고서 문안 초안을 **추가 집계 작업 없이** 얻을 수 있음
- 같은 사업의 연도별 만족도 변화를 대시보드에서 바로 볼 수 있음

## 8. 결정이 필요한 사항 (기본값으로 진행하고, 저장소 확인 후 조정)

| 번호 | 항목 | 기본값 | 확인 방법 |
|---|---|---|---|
| 1 | 직원 로그인 방식 | 기존 사이트의 로그인을 재사용, 없으면 Supabase Auth(Google, 협회 도메인 제한) | Phase 0 저장소 점검 |
| 2 | Supabase 프로젝트 | **설문 전용 신규 프로젝트**(서울 리전)로 분리. 기존 회원 데이터와 섞지 않음 | 담당자 결정 |
| 3 | 응답 저장소 | Supabase가 원본. Google Sheets로는 읽기용 내보내기만(선택) | 담당자 결정 |
| 4 | 결과 메일 발송 | Resend(또는 기관이 쓰는 메일 서비스) | 담당자 결정 |
| 5 | 공개 링크 도메인 | 기존 사이트 도메인의 `/s/<slug>` | 담당자 결정 |
