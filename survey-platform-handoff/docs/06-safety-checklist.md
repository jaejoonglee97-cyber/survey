# 06. 보안·개인정보 점검표

사회복지 현장에서 AI·바이브코딩으로 만드는 시스템에 적용하는 안전 사용 가이드(신용우, 2026.06 기준)의 원칙을 이 프로젝트에 맞춰 정리한 것임. 법률 자문이 아니며, 인용된 제도와 약관은 변경될 수 있으므로 실제 도입 전 기관 정보보안 담당자와 전문가의 검토를 받음.

> **한 줄 원칙**: 안 받아도 될 정보는 안 받고, 보내야 하면 가려서 보낸다. 진짜 정보를 넣기 전엔 더미 데이터로 테스트한다.

## 1. 이 시스템이 다루는 데이터

| 데이터 | 개인정보 여부 | 처리 |
|---|---|---|
| 응답(선택·점수) | 무기명이므로 원칙적으로 해당하지 않으나, 소규모 집단에서는 조합으로 식별될 수 있음 | 5건 미만 비공개, 분류 문항 겹쳐 묻기 금지 |
| 서술 의견 | 응답자가 이름·소속 등을 적을 수 있음 | 안내문으로 기재 금지, 담당자만 열람, AI 미전송, 보고서 인용 시 식별 정보 제외 |
| 직원 계정(이름·이메일) | 개인정보 | Supabase Auth, 최소 수집, 역할 분리 |
| 설계 대화 | 사업·행사 정보(개인정보 아님) | 개인정보 입력 금지 안내, 이메일·전화 형식 감지·마스킹 |

## 2. 바이브코딩 보안 4수칙

| 번호 | 수칙 | 이 프로젝트에서의 적용 | 점검 |
|---|---|---|---|
| 1 | 프롬프트에 보안을 명시 | `CLAUDE.md`와 단계별 지시문에 RLS·키 분리·입력 검증을 명시함 | ☐ |
| 2 | 키를 숨김 | `SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`, `CRON_SECRET`, `RESEND_API_KEY`는 서버 전용. `.env*` 커밋 금지 | ☐ |
| 3 | 더미 데이터로 먼저 | 시드는 더미만, Preview 는 별도 Supabase 프로젝트. 점검 완료 전 실제 설문 금지 | ☐ |
| 4 | 가장 강한 모델로 보안 검사 | Phase 8 에서 접근통제·키 노출·입력 검증·인젝션 검토 수행 | ☐ |

## 3. 배포 전 체크리스트

### 접근통제
- ☐ 모든 테이블 RLS 활성(`profiles`, `surveys`, `responses`, `builder_sessions`)
- ☐ anon 으로 어떤 테이블도 읽거나 쓸 수 없음(시험 통과)
- ☐ 열람자(viewer)가 응답 원자료와 설문 테이블을 읽을 수 없음(시험 통과)
- ☐ 응답 저장은 서버의 `submit_response`만 가능, 일반 로그인 사용자의 직접 insert 불가(시험 통과)
- ☐ 서버 라우트가 admin 역할을 직접 재확인함(화면 숨김에 의존하지 않음)
- ☐ 크론 라우트가 `CRON_SECRET` 없이는 401
- ☐ 신규 가입자가 viewer 로 시작하고, 관리자 승격은 관리자만 가능
- ☐ 로그인 허용 이메일 도메인(협회 워크스페이스) 제한 설정

### 키와 설정
- ☐ 클라이언트 번들에 service_role·Anthropic 키 문자열 없음(빌드 후 검색 스크립트)
- ☐ `NEXT_PUBLIC_` 변수에 비밀 값 없음
- ☐ git 이력에 `.env`·키가 없음(있으면 키를 폐기하고 재발급)
- ☐ Production/Preview 환경변수 분리, Preview 는 더미 DB
- ☐ 2단계 인증: GitHub, Vercel, Supabase, Anthropic, 메일 서비스 계정 모두 설정
- ☐ 퇴사·인사이동 시 계정 회수 절차 문서화

### 입력 검증과 인젝션
- ☐ 응답 API: 본문 20KB 제한, zod/survey-core 검증, 보기 외 값 거부
- ☐ 모든 사용자 입력은 텍스트로만 렌더링(`dangerouslySetInnerHTML` 없음), 문항·서술·제목에 HTML 을 넣어도 실행되지 않음(시험)
- ☐ CSV 내려받기에서 `= + - @` 로 시작하는 값에 수식 주입 방어
- ☐ 속도 제한(Vercel Firewall 규칙)과 응답 수 상한(5,000건/설문) 설정
- ☐ IP·User-Agent 미저장 확인

### AI 사용
- ☐ Claude API 는 서버에서만 호출, 응답 원문·서술 의견·개인정보를 보내지 않음
- ☐ 설계 대화에 이메일·전화 형식 입력 시 경고·마스킹
- ☐ AI 는 게시·마감·삭제 도구가 없고, 담당자의 확정 버튼으로만 게시됨
- ☐ 'AI 보조 작성 · 담당자 최종 검토' 표시
- ☐ 이전 설문 불러오기는 문항과 집계(5건 이상)만 포함하고 서술 의견은 제외
- ☐ 사용자 입력·첨부 파일·이전 설문 문구 안의 지시문을 따르지 않음(프롬프트 주입 시험 통과)
- ☐ 로그에 대화 내용이 남지 않음
- ☐ Anthropic API 의 보관·학습 정책을 도입 시점 약관으로 확인(가이드 기준: 학습에 사용하지 않음, 기본 보관 기간 있음)

### 저장 위치와 위탁
- ☐ Supabase 프로젝트가 **기관이 소유·관리하는 계정**에 있음(개인 계정 아님)
- ☐ 리전 서울(ap-northeast-2), Vercel Functions `icn1`
- ☐ **Supabase DPA 직접 서명**(자동 포함되지 않음, 대시보드 법무 문서에서 서명해야 발효)
- ☐ Vercel·메일 서비스(Resend 등)의 위탁 관련 약관 확인
- ☐ 서울 리전 지정 시 국외이전 동의 면제 여부와 그 외 서비스(메일 등)의 국외 처리 여부를 정보보안 담당자가 확인

### 개인정보 최소화와 공개 범위
- ☐ 수집 항목이 최소화됨(응답에 식별 정보 없음, 서버 검증으로 PII 문항 차단)
- ☐ 대시보드 5건 미만 비공개(시험 통과), 소규모 집단 분류 문항 겹쳐 묻기 경고
- ☐ 응답 화면에 처리 안내(무기명, 목적, 서술 기재 금지) 문구
- ☐ 결과보고서·대시보드 공유 범위(열람자 목록) 합의
- ☐ 보관 기간과 삭제 절차 합의(예: 사업 종료 후 N년, 담당자 삭제 권한)

## 4. 안전하지 않은 흔한 실수 (이 프로젝트에서 막아야 할 것)

| 실수 | 방지 |
|---|---|
| "일단 열어 두고 나중에 잠그자"(RLS 비활성) | 처음부터 RLS 활성, 시험이 실패하면 배포 불가 |
| 브라우저에서 service_role 키 사용 | 서버 라우트 전용, 번들 검사 |
| 실제 응답으로 개발·시험 | 더미 시드만 사용 |
| 서술 의견을 AI 에 붙여 넣어 요약 | v1 에서 기능 제외, 필요 시 동의·마스킹 설계 후 별도 단계 |
| 응답자 집단을 잘게 나누는 문항 | 서버 경고 + 5건 미만 비공개 |
| 개인 계정에 응답 데이터 저장 | 기관 계정·기관 프로젝트만 사용 |

## 5. 점검 결과 기록
